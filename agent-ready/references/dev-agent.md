# The `dev:agent` contract

One command gives the current checkout its own running app, with data, that
no other checkout or person shares. Agents run in parallel worktrees on one
host; everything below follows from that.

- **Isolated state.** Its own database or backend per worktree: a container
  and volume keyed by the worktree path, a per-branch cloud dev deployment,
  or a local file. Never a deployment someone else uses; refuse staging and
  production identifiers and live keys outright.
- **Ports from the path.** Derive every port from a hash of the absolute
  worktree path (the main checkout may keep the default). Bind to
  `127.0.0.1`. Two worktrees never collide, and a rerun reuses the same
  ports.
- **Generated config is marked.** Write `.env.local` with a first-line marker
  such as `# generated by dev:agent`, and refuse to overwrite one without it.
  Secrets come from a single documented place (the main checkout's env file
  or a user config file), are read inside the process, and are never printed.
- **Seeded, idempotently.** Demo data a user would recognise, invented (no
  real hostnames, emails or ids), written through the same validation as user
  actions. Fill what is missing on every run; `--reseed` starts from empty.
  Seeding refuses to run unless an explicit dev-only flag is set.
- **Test accounts**, one per role, with a password from the documented secret
  place.
- **A banner.** When ready, print the app URL(s), the accounts and where
  their password lives, and how to stop. `--status` prints it again.
- **Lifecycle.** The backend may outlive the command, so reruns are fast.
  `--down` removes this worktree's resources. Label everything created
  (`<project>.worktree=<path>`, `<project>.owner=<uid>`) and remove labelled
  resources whose worktree no longer exists. Never prune globally, never kill
  by name pattern: only PIDs you spawned, or the owner of your port after
  checking its cwd.
- **Non-interactive.** No prompts; stdin closed; exit non-zero with one clear
  line on failure.
- **Optional flags** only when the project needs them: `--integrations` to
  connect real external services read-only, `--share` to expose the instance
  on the tailnet for the user.

Record the design in an ADR. CI's end-to-end job should start the same
backend the same way.
